# כתר הנדסה — מערכת ניהול פרויקטים

מערכת ווב פנימית לניהול משימות, פרויקטים ולוחות זמנים עבור חברת ניהול ופיקוח
פרויקטי בנייה. נבנתה עם דגש על שיתוף פעולה בין שני השותפים בחברה.

## מה יש במערכת (v1)

- **התחברות** — חשבון אחד משותף לחברה (אימייל וסיסמה אחת), ואחרי ההתחברות
  כל אחד מהשותפים בוחר את השם שלו כדי לשייך אליו משימות ופעילות.
- **לוח בקרה** — סיכום כללי: משימות פתוחות ובאיחור, פרויקטים פעילים, עומס
  עבודה לפי שותף, מועדי יעד קרובים, פעילות אחרונה ופילוח פרויקטים לפי סטטוס.
- **משימות** — לוח קנבן משותף (לביצוע / בתהליך / לבדיקה / הושלם) עם גרירה
  ושחרור בין עמודות, סינון לפי אחראי/פרויקט/עדיפות, עריכה ומחיקה.
- **פרויקטים** — רשימת פרויקטים עם סטטוס, לקוח, כתובת ותקציב; דף פרויקט
  מפורט עם ציר זמן של אבני דרך והמשימות המשויכות אליו.
- **יומן פגישות** — לוח שנה חודשי משותף לשני השותפים, עם אפשרות סנכרון
  דו-כיווני עם Google Calendar האישי של כל אחד (ר' "חיבור Google Calendar"
  למטה - שלב הגדרה נפרד ואופציונלי).
- **פיתוח עסקי** — מעקב נפרד אחר הזדמנויות/לידים להבאת פרויקטים חדשים,
  עם רשימת משימות פתוחה (לא רשימה סגורה) לכל הזדמנות, וכפתור לקביעת
  פגישה שמקשר ישירות ליומן.

## פריסה לאינטרנט (מומלץ — בלי טרמינל, בלי התקנות)

זו הדרך המומלצת אם אין לכם Node.js מותקן, ואם אתם רוצים גם לגלוש למערכת
מהנייד. הכל נעשה דרך הדפדפן: [Neon](https://neon.tech) (מסד נתונים
PostgreSQL בענן, טייר חינמי) + [Vercel](https://vercel.com) (אחסון
האתר, טייר חינמי).

### שלב 1 — יצירת מסד נתונים ב-Neon

1. היכנסו ל-https://neon.tech והירשמו (אפשר עם חשבון Google).
2. צרו פרויקט חדש (Create a project) — אפשר להשאיר את כל ברירות המחדל.
3. במסך שנפתח יופיע **Connection string** — העתיקו אותו. הוא נראה כך:
   `postgresql://user:password@ep-xxxxx.neon.tech/neondb?sslmode=require`
   זה יהיה ה-`DATABASE_URL` שלכם בשלב הבא.

### שלב 2 — פריסה ב-Vercel

1. היכנסו ל-https://vercel.com והירשמו **עם חשבון GitHub** (חשוב שיהיה
   אותו חשבון GitHub שדרכו הריפו הזה נגיש).
2. לחצו **Add New… → Project**, ובחרו את הריפו `23RK/ceter-engineers`.
3. תחת **Branch** בחרו את `claude/keter-engineering-project-management-ir73dj`
   (או `main`, לאחר שהעבודה תמוזג אליו).
4. פתחו את **Environment Variables** והוסיפו שני משתנים:

   | Name | Value |
   | --- | --- |
   | `DATABASE_URL` | ה-connection string מ-Neon (שלב 1) |
   | `SESSION_SECRET` | מחרוזת אקראית וארוכה משלכם (40+ תווים) — למשל תוצאה של [מחולל סיסמאות אקראי](https://1password.com/password-generator) באורך 40. **אל תשתמשו בערך שמופיע במקום אחר בפומבי** — זה המפתח שחותם על ההתחברות שלכם. |

5. לחצו **Deploy** וחכו כדקה-שתיים. תהליך הבנייה מריץ אוטומטית את הגדרת
   מסד הנתונים ואת יצירת חשבון ההתחברות — אין צורך בשום פעולה נוספת.
6. בסיום תקבלו קישור כמו `https://ceter-engineers.vercel.app` — זה
   הקישור למערכת, זמין גם מהמחשב וגם מהנייד (אפשר לשמור אותו כקיצור דרך
   על מסך הבית בטלפון).

מתחברים עם:

| אימייל | סיסמה |
| --- | --- |
| keterengineers@gmail.com | keter2026! |

**מומלץ להחליף את הסיסמה** לאחר ההתחברות הראשונה, דרך "הגדרות" בתפריט הצד
באתר עצמו (יש לדעת את הסיסמה הנוכחית כדי לשנות אותה).

כל פעם שדוחפים שינוי קוד לענף המחובר, Vercel יבנה ויפרוס גרסה חדשה
אוטומטית לאותו קישור.

## חיבור Google Calendar (אופציונלי, אחרי שהאתר כבר באוויר)

בלי השלב הזה, "יומן פגישות" עדיין עובד מצוין כלוח שנה משותף בתוך המערכת -
זה רק מוסיף סנכרון עם היומן האישי של כל שותף ב-Gmail. **הכיוון מהמערכת
ל-Google מיידי** (פגישה שנקבעת באתר מופיעה תוך שניות ביומן Google של כל
שותף מחובר). **הכיוון ההפוך** (שינוי שנעשה ישירות ב-Google Calendar) נכנס
למערכת כשנכנסים לעמוד "יומן פגישות" (סנכרון אוטומטי בכניסה), ובכל רגע דרך
כפתור "רענון מיומן Google" - לא צריך לחכות לרקע. אם קרתה התנגשות (שני
עדכונים לאותה פגישה) - העדכון המאוחר יותר מנצח.

### שלב 1 — יצירת פרויקט ב-Google Cloud

1. היכנסו ל-https://console.cloud.google.com (עם כל חשבון Google).
2. צרו פרויקט חדש (בתפריט העליון: New Project) - שם כלשהו, למשל
   "כתר הנדסה".
3. חפשו **"Google Calendar API"** בסרגל החיפוש העליון, ולחצו **Enable**.

### שלב 2 — מסך הסכמה (OAuth consent screen)

1. בתפריט הצד: **APIs & Services → OAuth consent screen**.
2. סוג משתמש: **External**, ולחצו Create.
3. מלאו שם אפליקציה ("כתר הנדסה") ואימייל תמיכה (אפשר keterengineers@gmail.com).
4. בעמוד **Test users**, הוסיפו את **שתי כתובות ה-Gmail האישיות** של רון
   וגיא (החשבונות שדרכם תתחברו ליומן, לא בהכרח keterengineers@gmail.com).
   כך שהאפליקציה תישאר במצב "Testing" ותעבוד לשניכם בלי תהליך אישור
   (verification) של Google, שמיועד לאפליקציות ציבוריות.

### שלב 3 — יצירת פרטי OAuth

1. **APIs & Services → Credentials → Create Credentials → OAuth client ID**.
2. סוג: **Web application**.
3. תחת **Authorized redirect URIs** הוסיפו:
   `https://<הקישור-שלכם-מ-Vercel>/api/google/callback`
   (למשל `https://ceter-engineers.vercel.app/api/google/callback`)
4. לחצו Create - תקבלו **Client ID** ו-**Client Secret**. העתיקו את שניהם.

### שלב 4 — הוספת משתני סביבה ב-Vercel

בפרויקט שלכם ב-Vercel: **Settings → Environment Variables**, הוסיפו:

| Name | Value |
| --- | --- |
| `GOOGLE_CLIENT_ID` | מה-Google Cloud Console (שלב 3) |
| `GOOGLE_CLIENT_SECRET` | מה-Google Cloud Console (שלב 3) |
| `APP_URL` | הקישור המלא לאתר שלכם, בלי `/` בסוף - למשל `https://ceter-engineers.vercel.app` |
| `TOKEN_ENCRYPTION_KEY` | מחרוזת הקסדצימלית אקראית באורך 64 תווים (32 בייט) - משמשת להצפנת פרטי ההתחברות ל-Google שנשמרים במסד הנתונים. **בקשו מקלוד לייצר לכם ערך** (לא לשתף את הערך הזה בשום מקום פומבי). |

לאחר ההוספה - **Deployments → ⋮ → Redeploy** בפריסה האחרונה, כדי שהשינוי
ייכנס לתוקף.

### שלב 5 — חיבור בפועל

בעמוד "יומן פגישות" באתר, כל שותף (כשהוא מחובר ובחר את עצמו) לוחץ
**"חיבור"** ליד השם שלו, מתחבר עם חשבון ה-Gmail האישי שלו ומאשר גישה
ליומן. זהו - מכאן זה עובד לבד.

## הרצה מקומית (למי שיש Node.js)

```bash
npm install
cp .env.example .env      # לעדכן DATABASE_URL (ר' שלב 1 למעלה, או פוסטגרס מקומי) ו-SESSION_SECRET
                           # (משתני ה-Google אופציונליים - בלעדיהם "יומן פגישות" עובד בלי סנכרון)
npm run db:migrate        # יוצר את הטבלאות במסד הנתונים לפי הסכמה
npm run db:seed           # יוצר את חשבון ההתחברות המשותף + נתוני דוגמה
npm run dev
```

האתר יעלה בכתובת http://localhost:3000, עם אותם פרטי התחברות שמופיעים
למעלה.

שני השותפים מתחברים עם אותו אימייל וסיסמה, ואז בוחרים במסך הבא איזה מהשניים
הם ("רון" או "גיא") — כדי שמשימות ופעילות ישויכו לאדם הנכון. אפשר להחליף
משתמש בכל רגע דרך "החלפת משתמש" בתפריט הצד, בלי להתחבר מחדש.

## טכנולוגיה

Next.js 16 (App Router, TypeScript) · Tailwind CSS 4 · Prisma ORM ·
PostgreSQL · אימות מבוסס עוגיית JWT (ללא ספריית auth חיצונית) · React
Server Actions לכל הפעולות (יצירה/עריכה/מחיקה) ללא צורך ב-API נפרד.

פקודת ה-`build` מריצה אוטומטית `prisma migrate deploy` (מעדכן את מבנה
מסד הנתונים) ואת `prisma/seed.ts` (יוצר את חשבון ההתחברות אם הוא עוד לא
קיים) לפני בניית האתר — כך שפריסה ב-Vercel לא דורשת אף פעולת הגדרה ידנית
במסד הנתונים.

## מבנה הפרויקט

```
prisma/schema.prisma        סכמת מסד הנתונים (Credential, User, Project, Task, Lead, Meeting, GoogleAccount ...)
prisma/seed.ts              נתוני התחלה: חשבון ההתחברות המשותף, 2 פרופילי השותפים + נתוני דוגמה
src/lib/auth.ts             זיהוי ה-session וה"שותף" הפעיל בכל בקשה
src/lib/session.ts          חתימה ואימות של עוגיית ה-session (JWT)
src/lib/crypto.ts           הצפנה/פענוח (AES-256-GCM) לטוקנים של Google
src/lib/google/*.ts         OAuth, קריאות ל-Calendar API, ולוגיקת הסנכרון הדו-כיווני
src/lib/actions/*.ts        כל הפעולות מול מסד הנתונים (Server Actions)
src/app/login                מסך התחברות עם חשבון החברה המשותף
src/app/choose-user           מסך בחירת השותף (רון / גיא) אחרי ההתחברות
src/app/api/google/*         נקודות הקצה של תהליך ה-OAuth מול Google
src/app/(app)/*              העמודים המוגנים: לוח בקרה, משימות, פרויקטים, יומן פגישות, פיתוח עסקי
src/components/*             רכיבי UI
```

## רעיונות להמשך

- ניהול משתמשים דרך ה-UI (הוספת שותף/עובד נוסף)
- תגובות/דיון על משימה ספציפית
- קבצים מצורפים למשימה/פרויקט (מסמכים, תמונות מהאתר)
- התראות מייל על משימות שעומדות להתאחר
- תצוגת שבוע ביומן הפגישות (כרגע חודשי בלבד)
- סנכרון Google ברקע ללא צורך בכניסה לעמוד היומן - דורש שדרוג ל-Vercel
  Pro (ר' דיון בשלב התכנון); כרגע הסנכרון ההפוך מ-Google הוא בכניסה
  לעמוד + כפתור רענון ידני, לא רקע אוטומטי
